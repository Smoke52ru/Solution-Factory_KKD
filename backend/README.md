# Mock API модуля ККД — контроль качества данных по целям

Учебный mock API для тестового задания Frontend-разработчика. Он отдаёт результаты
**контроля качества данных (ККД)** по целям и ключевым результатам (КР) сотрудников:
метрики качества с учётом каскадирования, найденные проблемы и дельту с прошлым
прогоном.

Данные синтетические: оргструктура, сотрудники, цели и КР сгенерированы и к реальным
системам отношения не имеют. Всё хранится в памяти, перезапуск или `POST /api/reset`
возвращает демо-данные в исходное состояние.

> Для тестового задания нужны не все эндпоинты: обязательный список — в самом задании,
> остальные можно использовать по желанию.

> Визуальная часть задания — по файлу [UI-KIT.md](UI-KIT.md): токены платформы
> и готовая тема Ant Design, которую можно скопировать целиком.

## Запуск

```bash
# нужен Docker
docker compose up --build
```

```bash
# или локально (Python 3.11+)
pip install -r requirements.txt && uvicorn app.main:app --reload
```

- Swagger UI: http://localhost:8000/docs
- OpenAPI: http://localhost:8000/openapi.json
- Параметры датасета: `GET /health`
- Тесты: `pytest -q`

Переменные окружения — в `.env.example` (скопируйте в `.env`, если нужно поменять):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `MOCK_LATENCY_MS` | `300` | Задержка каждого ответа `/api/*`, чтобы были видны состояния загрузки |
| `MOCK_RUN_DURATION_SEC` | `6` | Сколько секунд выполняется прогон, запущенный через `POST /api/runs` |
| `MOCK_TODAY` | текущая дата | Зафиксировать «сегодня» (`YYYY-MM-DD`) |

## Предметная область

- **Цель** — заводится в модуле «Цели». Уровни каскада: `block` (цель блока) →
  `hq` (цель департамента) → `unit` (цель подразделения) → `employee` (цель сотрудника).
  Каждая цель, кроме уровня блока, привязана к родительской цели вышестоящего уровня.
- **Ключевой результат (КР)** — измеримый результат цели: единица измерения,
  базовое, целевое и фактическое значение, вес в процентах.
- **Прогон ККД** — еженедельная (по понедельникам) проверка снимка данных набором
  правил. Каждый прогон сравнивается с **предыдущим успешным** прогоном.
- **Проблема** — нарушение одного правила одной целью или одним КР. У проблемы
  стабильный `id` между прогонами, поэтому видно, новая она, сохраняется или исправлена.
- **Каскад в метриках** — метрики подразделения считаются по самому подразделению
  и всем дочерним (департамент = департамент + его управления и отделы).

Справочник правил, уровней важности и метрик с формулами отдаёт `GET /api/meta`.

| Код правила | Объект | Важность | Что проверяет |
|---|---|---|---|
| `GOAL_NO_OWNER` | цель | critical | Не указан ответственный |
| `GOAL_NO_KR` | цель | critical | Нет ни одного КР |
| `KR_WEIGHTS_SUM` | цель | major | Сумма весов КР ≠ 100% |
| `CASCADE_NO_PARENT` | цель | major | Нет связи с целью вышестоящего уровня |
| `CASCADE_WRONG_LEVEL` | цель | major | Родительская цель не выше по уровню или из другой ветки оргструктуры |
| `CASCADE_PARENT_INACTIVE` | цель | minor | Родительская цель закрыта или отменена |
| `GOAL_DEADLINE_OUT_OF_PERIOD` | цель | minor | Срок вне периода целеполагания (календарный год) |
| `GOAL_DUPLICATE` | цель | minor | У сотрудника есть активная цель с тем же названием |
| `KR_NO_TARGET` | КР | major | Не заполнено целевое значение |
| `KR_NO_UNIT` | КР | major | Не указана единица измерения |
| `KR_STALE_PROGRESS` | КР | minor | Факт не обновлялся более 45 дней |
| `KR_FACT_OUTLIER` | КР | minor | Факт больше цели более чем в 3 раза |

## Эндпоинты

| Метод и путь | Что возвращает |
|---|---|
| `GET /api/meta` | Оргструктура (`units` с `parent_id` и `depth`), правила, уровни важности, уровни целей, метрики с формулами |
| `GET /api/runs?limit&offset` | История прогонов (новые сверху): статус `completed` / `failed` / `running`, дата снимка, с каким прогоном сравнивается, итоги |
| `GET /api/runs/{run_id}` | Один прогон — для опроса статуса после запуска |
| `POST /api/runs` | Запустить внеплановый прогон → `202`, статус `running` около 6 секунд. Если прогон уже идёт — `409` |
| `GET /api/kkd/summary?run_id&unit_id` | Сводка: метрики (`value`, `previous`, `delta`, `delta_pct`, `trend`), проблемы по важности и по правилам с дельтой, счётчики `new` / `persisting` / `resolved` |
| `GET /api/kkd/units?run_id` | Метрики по каждому подразделению оргструктуры с учётом каскада и дельтой доли корректных целей |
| `GET /api/kkd/issues` | Список проблем с фильтрами и пагинацией (`items`, `total`, `limit`, `offset`) |
| `GET /api/kkd/issues/export` | Те же фильтры, выгрузка в CSV (UTF-8 с BOM, разделитель `;`) |
| `GET /api/kkd/issues/{issue_id}?run_id` | Карточка проблемы и `history` — была ли она в каждом прогоне |
| `GET /api/kkd/trend?unit_id&metric&limit` | Значения метрики по последним прогонам (у неуспешного прогона `value: null`) |
| `GET /api/goals?run_id&unit_id&level&has_issues&q` | Список целей с числом проблем |
| `GET /api/goals/{goal_id}?run_id` | Карточка цели: КР, родительская и дочерние цели, проблемы |
| `POST /api/reset` | Вернуть демо-данные в исходное состояние |

Общие параметры:

- `run_id` — `RUN-001`…`RUN-008` или `latest` (по умолчанию — последний успешный прогон).
- `unit_id` — код подразделения из `/api/meta`, по умолчанию `B2B` (весь блок).

Фильтры `GET /api/kkd/issues`: `rule_code`, `severity`, `delta_status`
(несколько значений через запятую), `object_type` (`goal` / `key_result`),
`q` (поиск по ID и названию цели или КР, ФИО ответственного),
`sort` (`severity` / `age` / `unit` / `rule`), `limit` (до 200), `offset`.
Исправленные проблемы приходят только при `delta_status=resolved`.

Ошибки возвращаются в едином формате:

```json
{ "error": { "code": "RUN_FAILED", "message": "Прогон RUN-006 завершился с ошибкой — результатов нет" } }
```

Коды: `404` — `RUN_NOT_FOUND`, `UNIT_NOT_FOUND`, `GOAL_NOT_FOUND`, `ISSUE_NOT_FOUND`;
`409` — `RUN_FAILED`, `RUN_IN_PROGRESS`; `422` — `INVALID_PARAM` и ошибки валидации параметров.

## Демо-сценарии в данных

- **RUN-006 завершился с ошибкой** — у него нет результатов, `RUN-007` сравнивается с `RUN-005`,
  в тренде на месте `RUN-006` — `value: null`.
- **RUN-001 — первый прогон**: сравнивать не с чем, все `previous` и `delta` — `null`.
- **CIB-REG «Управление региональных продаж»** — реорганизация: в последнем прогоне у многих
  целей сломан каскад, доля корректных целей упала больше чем на 20 п.п.
- **HQ-SME «Департамент малого и среднего бизнеса»** — качество данных растёт от прогона к прогону,
  много исправленных проблем.
- **TX-SAL «Управление зарплатных проектов»** — в последнем прогоне проблем нет (100%).
- **TX-NEW «Отдел платёжных сервисов»** — новое подразделение, целей нет: метрики `null`.
- **Первая цель подразделения CIB-KEY** — «витрина»: у неё сразу 4 проблемы, которые
  не исправляются с первого прогона.
- **CIB-TRADE и TX-ACQ** — отменённые родительские цели, у дочерних целей
  `CASCADE_PARENT_INACTIVE`.
- **`POST /api/runs`** — внеплановый прогон на сегодняшнюю дату: часть проблем исправлена,
  появились новые.
